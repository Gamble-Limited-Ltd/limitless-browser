## 2. 0.3.0: things the plan missed (all go into the 0.3.0 card)
1. **Rotation hazard (blocker if missed).** `rotate.sh` recreates `lbgate` at 06:00 from the **working-tree**
   `deploy/docker-compose.yml`. Today `lbgate` has `depends_on: [relay]` and sits on `lb_relay`. Deleting the `relay`
   service on `main` before the deploy makes compose fail or detaches the live 0.2.3 gate from its relay, and members lose
   browsing the next morning. Fix: do **not** delete the service. Put `relay` under `profiles: ["relay"]`, make the gate's
   dependency `required: false`, keep `RELAY_URL` and `lb_relay` until S4. Prod then stops starting it; the rehearsal and
   the speed harness start it with `--profile relay`. Boss stops the old container once after the deploy (command in the
   release record). Compatible with both 0.2.3 and 0.3.0, so it is safe on `main` at any time.
2. **Saved "off" switch.** Members who saved `limitless:relay-fallback:v1` = `0` would have no relay at all in 0.3.0. The key
   is ignored while our relay is off (the switch shows "Public relays (until 1.0)", disabled), and kept for 1.0. Test added.
3. **Startup probe and notice.** `LB_relayStatus()` probes our `/wisp/` and offers third-party relays when it is down. In
   0.3.0 that probe is skipped (it would hit the 410 every boot); the router and `ownSockets` stay but are inert
   (`LB_FEATURE_OWNSOCKETS=0` in the 0.3.0 build).
4. **Access check moves to boot** (`SPEED.md` 3.5, edited). With public relays, `/wisp/` protects nothing and the service
   worker can open a cached shell for a removed member. The libcurl session now starts only after the gated `version.json`
   answered 200. Still client side; see Q4.
5. **Dead relays in the pool.** The 13-entry pool and `mages.io` come from upstream and were never needed in prod. Before the
   speed gate, probe each (WISP handshake plus one fixture fetch), drop dead ones, and record the list and date in the
   release record. A speed release on half-dead relays would feel slower than 0.2.3.
6. **Honest speed check.** The gate measures the client pipeline on fixtures. Members will feel 0.3.0 through public relays.
   Run the public-site set on 0.2.3 (home relay) and 0.3.0 (public pool) and show Boss both before the deploy (advisory).
7. **Rollback stub needs `deploy.sh`.** `deploy.sh` builds from `git archive <sha>`; `c88ce5e` has no `sw.js`, and a 404 or
   HTML answer does not remove an installed worker. The working-tree `deploy.sh` must inject the self-removing stub when the
   archived tree has none, and nginx in `c88ce5e` must serve it (check that `/sw.js` is not caught by the app location).
   Rehearse: install the 0.3.0 worker, roll back on the throwaway stack, confirm the worker is gone.
8. **All-relays-down card and first-load notice** are in 0.2b but in no card or UI section; added to the 0.3.0 card. Keep them
   small (the full error card set is S6).
9. **Admin and docs.** Admin Health would show the relay "down": the admin script reads `features.ownRelay=false` and says
   "Public relays" (`ADMIN.md` 1). Same commit: `CLAUDE.md` Relays paragraph, `HOSTING-AND-PERFORMANCE.md`, vault Service

## 3. 1.0 relay design: making 0.2b buildable
- **Reuse, do not write a new "token checker".** Speed caps, fair share, byte counts, Load Now and the 5 TB brake all need
  the WISP frame parser, and that is `wisp.ts`, `frames.ts`, `bandwidth.ts` in lbgate today. Run the **same lbgate image on
  the VPS in a relay mode** (`GATE_MODE=relay`: no members DB, no sign-in, accepts only signed relay tokens). That keeps "no
  personal data on the VPS" and avoids a second codebase.
- **Token:** HMAC or Ed25519, 5 minutes, claims = opaque member id (not the GLL ID sub), plan, weight, limits version;
  refreshed by the app before expiry through `POST /_lb/relay-token` (`MEMBERSHIP.md` 11).
- **No home port.** The VPS **polls** home lbgate over the existing public host (`/_lb/relay/sync`, shared secret, every
  1 s, small JSON both ways: revocations down, byte counts up). Nothing is opened at home, the tunnel only carries tiny API
  calls (not proxying), and "revoke within 2 s" still holds.
- **VPS steps Boss runs:** DNS-only A record, ufw 443, Let's Encrypt, compose up. Claude pastes them.
